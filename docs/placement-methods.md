# Сравнение четырёх способов распределения мест

Серия использует один журнал каждого турнира Elo-tire для FAR-tour,
Zhivora-Tour, Grin-Cycle и Grin-Elo. Для N=8, 16, 32 проводится по 10 000
повторов: 30 000 турниров и 120 000 расстановок. Победители боёв между методами
не меняются. Основной показатель — среднее абсолютное отклонение места (MAE).

Рейтинги: откалиброванный beta-prime, α=135.1, β=65.2, scale=530,
с усечением `[600,1900)`. Коэффициенты Elo-tire и `dR=200` сохранены.
[Модель боя](elo-tire-model.md), [калибровка рейтингов](beta-prime-calibration.md).

## FAR-tour по условию задачи

После каждого реального боя проигравшему добавляется поражение. При втором
поражении он выбывает. Первый выбывший получает N-е место, следующий N−1 и так
далее. Последний оставшийся получает первое место. Финал и суперфинал входят
в общую хронологию, поэтому призовые места сохраняются.

Это **индивидуальные** места 1…N. Прежнее поле `bracket` в симуляции содержит
другую расстановку: спортсмены, выбывшие на одной стадии сетки, делят место.
Оно сохранено для совместимости и не подменяет FAR-tour в новом сравнении.

## Zhivora-Tour: основной вариант по Pascal

Основная серия и CI используют `--zhivora-fixed-top 6`, выбранный пользователем
после сверки с Pascal. Это значение по умолчанию в CLI, Python API и скрипте сравнения:

1. Места 1–3 закрепляются по решающим боям. Место 4 получает спортсмен,
   выбывший при переходе от четырёх активных участников к трём: перед боем,
   определяющим третье место. Финал и возможный суперфинал идут позднее.
2. Два спортсмена, выбывшие непосредственно перед четвёртым, получают места
   5 и 6 по месту последнего победившего. Проигравший будущему четвёртому получает
   6; другой — 5. Эти места закрепляются до сортировки групп.
3. Остальные участники, начиная с 7-го места, делятся на группы по числу **реальных побед**. Группа
   с большим числом побед располагается выше.
4. Внутри группы первым идёт тот, кто последним проиграл участнику с меньшим
   номером итогового места. Используется последний победивший соперник,
   а не первый и не среднее по всем соперникам.
5. При равенстве сохраняется порядок жеребьёвки, как при устойчивой сортировке
   исходного списка в Pascal. Исходные рейтинги для разрешения равенств не используются.

Группы обрабатываются сверху вниз. Если место последнего победившего ещё не
назначено, используется временный ключ: следующее свободное место, затем
следующее за ним для очередного такого участника. Это правило сохранено из
группового прохода Pascal; последующее назначение мест не запускает повторную
сортировку предыдущей группы. Диагностика сохраняет победы, соперников,
известные места, временные ключи и порядок каждой группы.

Технические проходы не увеличивают число побед. Классификационные встречи
между двумя уже выбывшими не влияют на основной журнал распределения мест.
Неполный или противоречивый журнал не получает полной расстановки.

## Сверка с приложенными исходниками Pascal

Исходники предоставлены пользователем; сетевые, файловые и интерфейсные
действия приложения не исполнялись. Код прочитан как описание алгоритма.

| Файл | Роль | SHA256 исходного файла |
|---|---|---|
| Unit1.pas | Объявления `WinCount`, `LLos`, исходного списка и мест | `121c15ceb4e8ccc4cd321ed830ed254b474bc009d4e17d7de63ba4ac024b8b4b` |
| Unit11.pas | Учёт финальных побед, обработка 5–6, групповой проход | `09dec3c7cee22ab1e28b9985836c1fd3adeb38b4ed868b72b16662d0271c5550` |

`Unit1.pas`, строки 219–220: `LLos` хранит последнего победившего,
`WinCount` — число побед. В `Unit11.pas`, строки 342–348 и 351–357,
победителю прибавляется победа, проигравшему записывается последний победивший.

В исходном коде **места 1–6 определены до группового прохода**, а сортировка
групп начинается с 7-го. Именно этот вариант используется в основном сравнении.
Первоначальное текстовое описание фиксировало только 1–4; оно сохранено как
альтернатива `--zhivora-fixed-top 4`, сортирующая остальных начиная с 5-го.
Уже на приложенном контрольном журнале N=16 варианты дают разные места.
Предыдущая серия с фиксацией 1–4 доступна в истории Git; текущий отчёт и графики
заменены результатами нового запуска с фиксацией 1–6.

В Pascal имеются специальные ветви для расширенного набора претендентов на
5–6 и сравнение их веса при равенствах. Вес в данной модели не генерируется.
Поэтому вариант с фиксацией шести поддерживает категории N=8,16,22,32
и тривиальные N≤4; для иных N он явно отклоняется. Для N=22 используется та же
обычная ветвь, с проверкой двух последних выбывших перед четвёртым: их последние
победившие должны иметь разные известные места 1–4, одно из которых — четвёртое.
При несоблюдении условия метод возвращает ошибку, а не придумывает вес спортсменов.
[Три примера N=22](examples/n22/index.md) включают финал и суперфинал.
Альтернативный вариант
с фиксацией четырёх работает для всех поддерживаемых симуляцией N=1…32.

[Дословный групповой проход](../test/fixtures/zhivora_group_reference.pas)
содержит строки 1530–1570 `Unit11.pas`, приведённые к UTF-8/LF. Его массивная
сортировка пузырьком воспроизведена отдельно в валидаторе. Полное Windows-приложение
не компилировалось: приложены лишь две части проекта с зависимостями от других форм.
Порт и независимый пересчёт проверены на ручных контрольных журналах, финалах,
суперфиналах, регулярных размерах основного варианта и N=1…32 альтернативного.

## Grin-Cycle и Grin-Elo

Оба сначала выполняют существующий графовый проход и сохраняют призёров.
Grin-Cycle разрешает остаточные циклы по хронологии, поражениям и предварительным
местам, с равными весами критериев. Исходные рейтинги ему недоступны.
Grin-Elo при отказе графа использует исходные рейтинги соперников в резерве.
Они рассматриваются как два разных метода распределения мест.

## Метрики и неопределённость

Истинное место — позиция при сортировке исходных рейтингов по убыванию;
равные рейтинги разрешаются по ID. Для спортсмена δ = назначенное − истинное место.
MAE турнира равна `Σ|δ|/N`; общий показатель — среднее по полным турнирам метода.

Для каждого истинного места сохраняются прежние пять столбцов: место, Var(δ)
с ddof=0, mean(|δ|), максимум вниз и максимум вверх. Графики показывают те же
четыре показателя, но теперь все методы наложены на общие оси для данного N.
Отдельный график сравнивает MAE по истинным местам для N=8,16,32.

Дополнительно сохраняются Spearman, 95-й процентиль и максимум MAE турниров,
доля идеальных порядков и 95% интервалы среднего. Используется приближение
`mean ± 1.96·std(ddof=1)/sqrt(T)`. При T<2 интервал не определяется.

Все шесть пар методов сравниваются на одинаковых полных повторах. Для пары
сначала рассчитывается разность MAE внутри каждого турнира, затем её среднее
и интервал. Отрицательная разность означает меньшую MAE слева. Интервалы
характеризуют случайность моделирования при заданных коэффициентах и рассчитываются
для каждой пары отдельно; неопределённость калибровки коэффициентов сюда не входит.

10 000 повторов стабилизируют средние и показывают редкие исходы. Выбросы
не удаляются из выборки. Число полных и пропущенных расстановок показывается
отдельно. Совпадение присуждённых призовых мест не означает совпадения ошибок
истинных сильнейших участников, которые могли не попасть в тройку.

## Запуск

```bash
.venv/bin/python scripts/run_placement_comparison.py --repeats 10000 --seed 42

# Один размер категории через общий CLI:
.venv/bin/python -m simulation --elo-tire --far-tour --zhivora-tour \
  --grin-cycle --grin-elo --zhivora-fixed-top 6 \
  --participants 32 --repeats 10000 --seed 42 \
  --output results/placement-comparison/n32

# Короткая проверка: 100 повторов на каждый N, всего 300 турниров.
.venv/bin/python scripts/run_placement_comparison.py --smoke

# Альтернатива первоначального описания, в отдельном каталоге:
.venv/bin/python scripts/run_placement_comparison.py --zhivora-fixed-top 4 \
  --output results/placement-top4 --report results/placement-top4/report.md
```

Добавлены schema 6, поля мест и диагностики FAR/Zhivora, `ranking-metrics.csv`
с каждым повтором, доверительные интервалы и парные сравнения. Валидатор
независимо пересчитывает новые места и статистику. Старые команды без новых
методов сохраняют schema 5; чтение schema 4/5 сохранено.
