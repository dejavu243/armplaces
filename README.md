# ArmPlaces

Экспериментальное моделирование армрестлинга с выбыванием после двух поражений
и расстановка мест по алгоритму Гринёва (GrinTour). Проект сравнивает три модели
исхода боя с результатами сетки и эвристической расстановкой мест.

## Установка: только собственное виртуальное окружение

Поддерживаются Python 3.11–3.13. Все команды выполняются из корня репозитория.
Системный Python используется **только для создания `.venv`**; установка пакетов,
тесты и эксперименты запускаются интерпретатором проекта. Активация не требуется.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -v
.venv/bin/python -m ruff check .
```

`requirements-dev.txt` включает `requirements.txt` и Ruff. Для запуска без разработки
достаточно `.venv/bin/python -m pip install -r requirements.txt`.
В Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`.
`.venv`, кэши и каталог `results/` исключены из Git.

## Запуск: каждый эксперимент добавляется флагом

```bash
# Первый эксперимент: больший рейтинг всегда побеждает; дополнительно считаем GrinTour.
.venv/bin/python -m simulation --strong-win --grin-tour

# Добавляем независимый эксперимент с вероятностью Эло.
.venv/bin/python -m simulation --strong-win --elo --grin-tour

# Добавляем независимый эксперимент с усталостью.
.venv/bin/python -m simulation --strong-win --elo --elo-stamina --grin-tour \
  --participants 32 --repeats 1000 --seed 42 --output results/comparison

# Одна категория, один турнир, только места по сетке.
.venv/bin/python -m simulation --elo --participants 17 --repeats 1 \
  --seed 42 --output results/single

.venv/bin/python -m simulation --help
```

`--strong-win`, `--elo`, `--elo-stamina` выбирают **отдельные эксперименты**.
`--elo-stamina` не требует `--elo`. Можно выбрать любой непустой набор; порядок
флагов и повторение одного флага не меняют результаты. Без выбора эксперимента
CLI завершается с ошибкой. `--grin-tour` добавляет расчёт мест к каждому выбранному
эксперименту, но не определяет победителей боёв.

Каждая команда перезаписывает файлы своего каталога `--output`. Для сохранения
нескольких запусков задавайте разные каталоги.

| Параметр | По умолчанию | Смысл и ограничения |
|---|---:|---|
| `--strong-win` | выключен | Больший исходный рейтинг побеждает |
| `--elo` | выключен | Случайный исход по Эло |
| `--elo-stamina` | выключен | Случайный исход по Эло с усталостью |
| `--grin-tour` | выключен | Дополнительная эвристическая расстановка мест |
| `--participants` | 32 | Целое 1–128; N=1 обрабатывается без боёв |
| `--repeats` | 1000 | Положительное число независимых повторов на модель |
| `--seed` | 42 | Неотрицательное целое начальное состояние генераторов |
| `--alpha` | 2 | Положительный конечный параметр формы бета-прайм |
| `--beta` | 3 | Второй положительный конечный параметр формы |
| `--scale` | 1000 | Положительный конечный масштаб рейтинга |
| `--dr` | 200 | Положительный конечный масштаб вероятности Эло |
| `--k` | 160 | Неотрицательный конечный коэффициент обновления после турнира |
| `--fatigue-rate` | 0.05 | Доля накопления усталости, `0 ≤ f < 1`; влияет только на `--elo-stamina` |
| `--output` | `results/comparison` | Каталог артефактов |

## Генерация участников и генеральная последовательность

1. Для каждого повтора генерируются N независимых рейтингов:
   `G₁ ~ Gamma(α, 1)`, `G₂ ~ Gamma(β, 1)`, `R = scale · G₁/G₂`.
   Это бета-прайм распределение с положительным неограниченным хвостом.
   Рейтинги не округляются и не обрезаются. При численном переполнении или
   нулевом результате экстремальных параметров запуск завершается с объяснением.
2. Отдельный генератор случайно переставляет ID участников `0..N−1`.
   Все выбранные модели получают одинаковые рейтинги и жеребьёвку данного повтора.
3. Размер сетки S — ближайшая степень двойки не меньше N. Первые S/2 участников
   жеребьёвки занимают первые позиции пар, оставшиеся — вторые. Свободные позиции
   распределены по разным парам. При N=S пара i содержит участников жеребьёвки
   i и i+S/2; это равномерная случайная жеребьёвка, без посева по силе.
4. Генератор заранее строит матчи верхней (`W`) и нижней (`L`) сеток и адреса
   переходов победителя и проигравшего. Генеральная последовательность GS —
   линейный массив: позиции `2i`, `2i+1` содержат ID участников матча i.
   Рейтинги связаны с ID, поэтому одинаковые рейтинги не смешивают участников.
   Адреса в новой сетке нумеруются с нуля; `None` означает отсутствие перехода.
5. После `W1` проигравшие попарно играют `L1`. Далее проводится очередной тур W,
   его проигравшие в обратном порядке встречаются с оставшимися в L. Если в W
   ещё несколько победителей, L проводит дополнительный сокращающий раунд.
   Внутри раундов пары соседние. Для N=2 отдельного раунда L нет.
6. После каждого матча участники переходят в заранее определённые ячейки GS.
   При одном участнике происходит технический проход; при двух пустых позициях
   дальше передаётся пустая позиция. Эти события не считаются боями, победами,
   поражениями или нагрузкой и не потребляют случайный исход боя.
7. Участник выбывает после второго реального поражения. Победитель W встречается
   с победителем L в финале. Если победил участник L, у обоих по одному поражению:
   проводится суперфинал (`reset`). Иначе турнир завершён.
8. Чемпион получает место 1. Группы выбывших на одной стадии ранжируются в обратном
   порядке стадий. Группа делит место, последующее место учитывает её размер:
   например `1, 2, 3, 4, 5, 5, 7, 7` для полной категории из восьми участников.
   Дополнительных боёв за 5–6-е место нет.

При N≥2 получается `2N−2` реальных боёв без суперфинала или `2N−1` с ним.
Эти инварианты и журнал независимо проверяются после каждой симуляции.
Новая сетка намеренно отличается от исторической DE_OLD.

## Как выбирается победитель

### `--strong-win`

Более высокий **исходный** рейтинг всегда побеждает. При равенстве победитель
выбирается с вероятностью 1/2. Для уникальных рейтингов сильнейший всегда чемпион,
но остальные места не обязаны совпадать с порядком рейтингов из-за жеребьёвки.

### `--elo`

Для участников A и B:

```text
P(A) = 1 / (1 + 10^((R_B − R_A) / dR))
P(B) = 1 − P(A)
```

Генерируется U, равномерное на `[0,1)`: A побеждает при `U < P(A)`, иначе B.
При равных рейтингах P=0.5; при преимуществе 200 и dR=200 P=10/11.
Реализация вычисляет логистическую вероятность без переполнения экспоненты.

### `--elo-stamina`

Перед боем для каждого участника рассчитывается:

```text
R_eff = R_start · (1 − f)^m
```

Здесь m — число **предыдущих реальных боёв**, f=0.05 по умолчанию. В формулу Эло
подставляются эффективные рейтинги. После боя m увеличивается у обоих участников.
Нет восстановления и различия нагрузки победителя и проигравшего. Исходный рейтинг
не изменяется. Это выбранная экспериментальная модель, без физиологической калибровки.
При f=0 результаты `--elo` и `--elo-stamina` совпадают для одинакового seed.

### Обновление рейтинга после турнира

Во всех моделях после завершения вычисляется:

```text
R_new = R_start + K · Σ(S − P_start)
```

S=1 для победы, S=0 для поражения. Суммируются только реальные бои. `P_start`
рассчитывается по исходным рейтингам без усталости, даже для `--elo-stamina`.
K=160 влияет на итоговый рейтинг, но не на вероятность в текущем турнире.
Изменения двух соперников противоположны; рейтинг может стать отрицательным,
ограничения снизу и округления нет. В следующий независимый повтор R_new не переносится.

## Полный алгоритм Гринёва (`--grin-tour`)

Это эвристика расстановки мест **по уже известным результатам**. Ни исходный рейтинг,
ни усталость, ни вес спортсмена не участвуют в сравнении мест. Счётчики графа ниже
отличаются от реального числа побед и поражений в журнале.

### 1. Подготовка результатов

Вход: упорядоченный словарь участников и список пар `(проигравший, победитель)`.
В симуляциях порядок словаря — порядок жеребьёвки. Исходный журнал сохраняется.
Для графа создаётся отдельная проекция:

- Технические проходы исключаются.
- Повторения одного направления объединяются.
- Если A и B побеждали друг друга, сохраняется направление большинства побед.
- При равенстве встречных результатов сохраняются оба направления. Это цикл,
  поэтому результат будет `undefined`, а не произвольно выбранный порядок.

Если после этой обработки остаётся любой направленный цикл, расчёт останавливается
со статусом `undefined` и причиной. Некорректные имена или самовстречи — ошибки входа.

### 2. Цепочки и граф

В проекции находятся участники, которые никого не победили. От каждого строятся
все полные цепочки `участник → победивший его → победивший того → …` до вершины,
которую никто не победил. Для каждого начала отдельно находятся максимальная длина L
и цепочки длины L либо L−1. Короткие корректные цепочки тоже сохраняются.

Выбранные цепочки объединяются. Итоговые рёбра направлены **от победителя к проигравшему**.
Вес ребра — число его появлений в выбранных цепочках; это не число реальных побед.
Все участники добавляются в граф, включая изолированных.

Для рабочих запусков эквивалентные веса вычисляются динамическим программированием
по длинам префиксов и суффиксов путей. Все пути явно не перечисляются: это позволяет
обрабатывать большие категории. `make_all_chains()` оставлен для небольших примеров;
количество явных путей может расти экспоненциально.

### 3. Метрики графа и первые места

Для каждой вершины вычисляются неизменные метрики исходного итогового графа:

```text
wins = число исходящих рёбер
losses = число входящих рёбер
level = wins − losses + 2
```

Веса рёбер в этих формулах не используются. У графа должен быть ровно один источник
(вершина без входящих рёбер); иначе результат `undefined`.

Источник получает место 1. Пока текущая вершина имеет ровно одно исходящее ребро,
следующая вершина получает следующее место. При первом разветвлении этот шаг заканчивается.
Один участник получает место 1 без дополнительных действий.

### 4. Оставшиеся места снизу вверх

В рабочей копии графа выбираются ещё не размещённые конечные вершины — без исходящих
рёбер. Для каждой вычисляются критерии:

1. `chain_up_length`: максимальная длина пути от источника в вершинах — **по убыванию**.
2. Минимальный `level` непосредственно победивших её участников — **по возрастанию**.
3. Средний `level` этих участников — **по возрастанию**.
4. Максимальный `wins` этих участников — **по возрастанию**.
5. Позиция в исходном словаре/жеребьёвке — **по возрастанию**, если всё остальное равно.

Сравнение лексикографическое. Первый в таком списке получает худшее оставшееся место,
затем места уменьшаются. Поэтому при полном равенстве более ранняя позиция жеребьёвки
получает худшее место; это воспроизводимое техническое правило, а не спортивный критерий.
Размещённые конечные вершины удаляются, процесс повторяется. Ранее назначенные верхние
места не перезаписываются. Входные граф и словарь не изменяются.

После расчёта проверяется, что каждый участник получил ровно одно место от 1 до N.
Нет искусственного лимита 15 шагов для цепочек или 100 итераций расстановки.
Невозможность продолжения означает `undefined`, без частичного результата.

### Пример полного турнира из четырёх участников

Рейтинги A=400, B=300, C=200, D=100; жеребьёвка `[A,B,C,D]`, режим `--strong-win`.
Пары первого тура: A–C, B–D. Журнал `(проигравший, победитель)`:

```text
(C,A), (D,B), (D,C), (B,A), (C,B), (B,A)
```

Повтор `(B,A)` объединяется только для графа. Участник без побед — D. Цепочки:

```text
D → B → A          длина 3
D → C → A          длина 3
D → C → B → A      длина 4
```

Все три цепочки сохраняются (L=4 и L−1=3). Рёбра и веса:
`A→B:2`, `A→C:1`, `B→C:1`, `B→D:1`, `C→D:2`.

| Участник | wins графа | losses графа | level | Максимальная длина пути от A |
|---|---:|---:|---:|---:|
| A | 2 | 0 | 4 | 1 |
| B | 2 | 1 | 3 | 2 |
| C | 1 | 2 | 1 | 3 |
| D | 0 | 2 | 0 | 4 |

A получает место 1; у A два исходящих ребра, поэтому начальная цепочка заканчивается.
Конечная вершина D получает место 4 и удаляется, затем C получает 3, затем B — 2.
Итог: A, B, C, D. Рейтинг использовался только для моделирования боёв, не для GrinTour.

### Ограничения и отличия от первоначального описания

Исходный текст предлагает только максимальные цепочки; существовавший код сохранял
также L−1, и эта особенность сохранена. Неиспользовавшаяся длина пути вниз удалена.
Счётчики графа не учитывают веса, как и в исходной реализации. Равные критерии теперь
имеют явное правило разрешения. Циклы и несколько источников не скрываются усечением
или выбором первого источника. GrinTour не гарантирует совпадение ни с местами сетки,
ни с порядком силы участников. Его доля успешных расчётов — отдельная метрика.

## Исторические протоколы и DE_OLD

```bash
.venv/bin/python main.py --input data/left_hand_75kg --output results/historical
```

Читаются UTF-8-файлы с суффиксами `[DE].txt` (имена и последняя строка результатов),
`[ADE].txt` (веса), необязательные `[DE_5-6].txt` и `[DE_0_5-6].txt`.
В `[DE]` символ `+` означает победу первого, `-` — второго, `>`/`<` — соответствующий
технический результат. Технические результаты продвигают участников, но не добавляют бой.
В дополнительном протоколе 5–6 используется первый символ результата.
Имена с дефисами допустимы. Пропущенные обязательные файлы, дубли протоколов,
повреждённые результаты и конфликтующие переходы вызывают явную ошибку.

Оригинальные `data/DE_OLD_Winner.py` и `data/DE_OLD_Loser.py` **не изменены**.
Восстановление использует самостоятельные копии с суффиксом `_fix`:

| Копия | N | Исправление (номер пары и адрес с единицы) |
|---|---:|---|
| Loser_fix | 13 | Пара 18: проигравший 47 → 45; раньше оба попадали в 47 |
| Loser_fix | 16 | Пара 23: проигравший 59 → 57; раньше оба попадали в 59 |
| Loser_fix | 28 | Адреса проигравших пар 45/46: 105/131 → 131/105; выбывший попадал в следующий бой |
| Winner_fix | 23 | Блок пар 32–41 выровнен в `74,77,78,79,80,87,81,82,83,84`; устранены смещение и повтор адреса 82 |

Исправления проверяются проходом полных турниров для всех N=2–32 и 50 наборов исходов.
Они восстанавливают структурную корректность таблиц; исходные спортивные протоколы
и фотографии не переписываются. В старых таблицах адрес 0 означает отсутствие перехода,
а ненулевые адреса нумеруются с единицы. Записи в последнюю ячейку через индекс −1 нет.
`tournament_recovery()` теперь возвращает исходные реальные бои **с повторениями**;
проекция для графа выполняется отдельно.

## Артефакты, метрики и воспроизводимость

| Файл | Содержимое |
|---|---|
| `config.json` | Параметры, модели, статус запуска, seed, SHA Git, признак незакоммиченных изменений, версии Python и зависимостей |
| `participants.csv` | Повтор, модель, ID, позиция жеребьёвки, исходный/новый рейтинг, реальные W/L, число боёв, оба вида мест и статус Гринёва |
| `bouts.csv` | Журнал всех обработанных позиций, включая технические: стадия, соперники, исход, вероятности, эффективные рейтинги и предшествующая нагрузка |
| `tournaments.jsonl` | Одна запись на турнир: жеребьёвка, чемпион, суперфинал, заполненная GS и результат Гринёва |
| `summary.json` | Агрегированные метрики, размеры выборок и причины неопределённости |
| `report.md` | Краткий отчёт в виде таблицы |
| `run.log` | Прогресс, проверка артефактов и исключения |
| `console.log` | Дополнительный полный консольный лог в CI |

ID начинаются с 0, повторы с 0, позиции жеребьёвки и места с 1. Пустая ячейка CSV
означает отсутствие значения. Статусы Гринёва: `ok`, `undefined`, `disabled`.
В `participants.csv` W/L — реальные бои, не степени вершин GrinTour.

Метрики:

- Частота победы сильнейшего: доля турниров, где чемпион имеет максимальный исходный рейтинг.
- MAE: среднее абсолютное отличие места от исходного рейтингового ранга.
- Spearman: корреляция рангов. Общие места и равные рейтинги получают средние ранги.
- Доля `undefined`: отдельно для Гринёва. Такие турниры исключаются из его MAE/Spearman;
  `samples` и `correlation_samples` показывают фактический размер выборки.
- При N=1 или постоянных рангах корреляция математически не определена: сохраняется
  `null`, не NaN. При выключенном Гринёве его выборка пуста, метрики — `null`.

При одинаковом seed и окружении рейтинги, жеребьёвка и исходы воспроизводятся независимо
от порядка/набора выбранных моделей. Потоки NumPy задаются через `SeedSequence`:
`[seed, repeat, 0]` — рейтинги, `1` — жеребьёвка, `2` — обе модели Эло, `3` — strong-win.
Обе модели Эло используют общие случайные числа для сравнения; после расхождения исходов
те же числа могут относиться к другим парам. У разных моделей отдельные экземпляры генератора.
Между версиями зависимостей абсолютное совпадение не обещается; версии записаны в артефактах.
Время в логах и метаданные Git могут отличаться при одинаковых численных результатах.

Экспорт проверяется автоматически; его можно проверить отдельно:

```bash
.venv/bin/python -m simulation.verify results/comparison
```

### Python API

```python
from simulation import Config, generate_field, simulate
from simulation.experiments import run_experiments

config = Config(participants=16, repeats=1000, seed=42)
ratings, draw = generate_field(config, repeat=0)
result = simulate(config, "elo", ratings, draw, repeat=0, grin_tour=True)
summary = run_experiments(config, ["strong-win", "elo", "elo-stamina"],
                          grin_tour=True, output="results/api")
```

## CI: тесты и эксперименты для 16/32 участников

Workflow `.github/workflows/ci.yml` запускается на push, pull request и вручную.
Проверки работают на Python 3.11, 3.12, 3.13: создают `.venv`, устанавливают зависимости,
запускают Ruff и `unittest`. Тесты охватывают все N=2–128, финалы, пропуски, циклы,
усталость, отложенное обновление, CLI, воспроизводимость и проверку файлов.

После успешных проверок два отдельных job на Python 3.12 выполняют:

```bash
.venv/bin/python -m simulation \
  --strong-win --elo --elo-stamina --grin-tour \
  --participants 16 --repeats 1000 --seed 42 --output results/n16

.venv/bin/python -m simulation \
  --strong-win --elo --elo-stamina --grin-tour \
  --participants 32 --repeats 1000 --seed 42 --output results/n32
```

Каждый job выполняет 3000 турниров. Нарушение инвариантов, неполный экспорт или нечисловые
метрики приводят к падению job. Согласованный `undefined` Гринёва допустим.
Таблица метрик публикуется в Job Summary. Вывод через `tee` сохраняет код ошибки
благодаря `bash` с `pipefail`.

Артефакты **`simulation-n16-seed42`** и **`simulation-n32-seed42`** хранятся 30 дней.
Загрузка выполняется и после ошибки эксперимента: доступны частичные результаты и логи,
если они успели создаться. Откройте **Actions → Tests and simulation experiments → нужный
запуск → Artifacts** и скачайте архив. Это артефакты конкретного запуска, не файлы в Git.

Полная локальная серия (15 000 турниров):

```bash
for n in 8 16 32 64 128; do
  .venv/bin/python -m simulation --strong-win --elo --elo-stamina --grin-tour \
    --participants "$n" --repeats 1000 --seed 42 --output "results/n$n" || exit
done
```

Итоги контрольной серии приведены в [docs/experiment-report.md](docs/experiment-report.md).
Работа над реализацией ведётся в отдельной ветке `work/ci-simulation`, законченными коммитами.
